# خطوات المالك: النسخ الاحتياطي الليلي المشفّر إلى Cloudflare R2 (أو تخزين متوافق مع S3)

> ملاحظة لـ Claude: املأ القيم بين `< >` (اسم التثبيت `<NAME>`، الوقت، اسم المجلد، يوم النسخة الأسبوعية) قبل التسليم.
> R2 هو المسار المصمَّم والمراجَع؛ مزوّد S3 آخر يحتاج فحص قواعد القفل والحذف عنده قبل الاعتماد (توقّف واسأل).

هذه الخطوات تقوم بها أنت (لوحة Cloudflare + أمر واحد على الخادم). لا يرى Claude أي مفتاح أو كلمة مرور في أي مرحلة؛
بعد انتهائك يتحقق فقط من وجود الإعداد (أسماء الإعدادات وصلاحية الملف).

**ما يُنسخ كل ليلة الساعة `<الوقت>`** (مشفّراً على الخادم قبل الرفع): قاعدة بيانات Moodle بنسخة متسقة دون قفل الجداول،
وملفات المستخدمين `filedir` (الأولى كاملة ثم الجديد فقط، مع مزامنة كاملة ليلية رخيصة في R2)، والإعدادات ومنها مفتاح
`secret/` (**بدون** كلمة مرور خدمة البريد)، وكود Moodle أسبوعياً وكلما تغيّر.

> **مهم:** اختر مزوّد تخزين **غير** مزوّد الخادم (مثلاً خادم على DigitalOcean ونسخ على Cloudflare R2)، حتى لا تضيع
> النسخ والخادم معاً بسبب مشكلة في حساب واحد.

---

## 0. قبل البدء: مدير كلمات المرور

مدخل واحد **مشترك بين شخصين على الأقل**:

| البند | سري؟ | من أين |
|---|---|---|
| اسم الـ bucket واسم مجلد هذا الخادم | لا | الخطوة 2 والسكربت |
| Account ID (‏32 حرفاً hex) | لا | الخطوة 1 |
| Access Key ID | نعم | الخطوة 5 |
| Secret Access Key | نعم (يظهر مرة واحدة فقط) | الخطوة 5 |
| عبارة التشفير (crypt passphrase) | نعم | ولّدها: 32 حرفاً أو أكثر، حروف وأرقام، بلا مسافات |
| عبارة الملح (salt passphrase) | نعم | عبارة ثانية مختلفة بالشروط نفسها |
| رابط فحص النبض `HC_URL` | شبه سري | الخطوة 7 |
| مرفق: سكربت الإعداد `owner-setup-s3.sh` | لا | لا يحتوي أي سر، ويلزم لإعادة بناء الإعداد |

> **تحذير:** بدون عبارتي التشفير والملح **لا يمكن لأحد قراءة النسخ**، لا نحن ولا Cloudflare. احفظ نسخة خارج الإنترنت.
> فقدان المفتاح (Access Key) أمر بسيط: يُنشأ غيره. لكل خادم عبارتان ومجلد خاص.

قبل أي أمر تكتب فيه أسراراً: `unset HISTFILE` في الجلسة نفسها، وإذا توقف السكربت برسالة خطأ فلا تلصق شيئاً بعدها.

## 1. تفعيل R2 وحماية الحساب

1. لوحة Cloudflare: **المصادقة الثنائية (2FA) إلزامية**، وأضف **مسؤولاً ثانياً** للحساب.
   > أي مسؤول في حساب Cloudflare يستطيع حذف قاعدة القفل، لذلك حماية النسخ الحقيقية هي حماية الدخول إلى الحساب.
2. **Storage & Databases ← R2 Object Storage**، ثم الاشتراك في R2 (تُطلب وسيلة دفع حتى ضمن الحصة المجانية).
3. انسخ **Account ID** من **Account Details** إلى مدير كلمات المرور.

## 2. إنشاء الـ bucket

1. **Create bucket**، الاسم مثلاً `<اسم المنصة>-backups` (حروف صغيرة وأرقام وشرطة، بلا معلومة سرية). يمكن أن يخدم
   الـ bucket نفسه عدة خوادم، لكل خادم مجلده.
2. **Location:** Automatic مع **Location hint** في منطقة مسجّلة في سجل البيانات الشخصية، ويفضّل بعيداً عن منطقة الخادم.
3. **Jurisdiction:** افتراضي، أو EU إن اخترتها (ستجيب `eu` في السكربت).
4. **Storage class:** Standard. اترك الـ bucket **خاصاً**: لا Public access ولا `r2.dev` ولا Custom domain.

## 3. قواعد الحذف التلقائي (Object lifecycle rules)

**Settings ← Object lifecycle rules ← Add rule**، قاعدة لكل سطر (`<المجلد>` = اسم مجلد هذا الخادم):

| Prefix (بالضبط، مع الشرطة المائلة) | Delete uploaded objects after |
|---|---|
| `<المجلد>/daily/` | **8** days |
| `<المجلد>/weekly/` | **29** days |
| `<المجلد>/monthly/` | **186** days |
| `<المجلد>/code/` | **29** days |
| `<المجلد>/filedir-deleted/` | **186** days |

- **لا** قاعدة على `<المجلد>/filedir/` (هي النسخة الحالية من الملفات)، ولا على `<المجلد>/keycheck/` (ملف صغير يثبت
  صحة عبارتي التشفير، يبقى دائماً).
- أضف **Abort incomplete multipart uploads** بعد **1** day على الـ bucket كله.

## 4. قواعد القفل (Bucket lock rules)

**Settings ← Bucket lock rules ← Add rule ← Retain for a specified duration**. مدة كل قفل **أقل بيوم** من قاعدة الحذف
للمجلد نفسه، وإلا لن تعمل قاعدة الحذف:

| Prefix | مدة القفل |
|---|---|
| `<المجلد>/daily/` | 7 days |
| `<المجلد>/weekly/` | 28 days |
| `<المجلد>/monthly/` | 185 days |
| `<المجلد>/code/` | 28 days |

- **لا** تقفل `filedir/` ولا `filedir-deleted/` ولا `canary/` ولا `keycheck/` ولا الـ bucket كله: مرآة الملفات تحتاج
  الحذف والنقل.
- إن اختلفت تسميات اللوحة عمّا هنا فتوقّف وراجعني قبل الحفظ.
- ملاحظة: طلب حذف بيانات شخص لا يصل إلى نسخة شهرية مقفلة قبل انتهاء قفلها (حتى 185 يوماً). سجّل ذلك في سجل البيانات.

## 5. مفتاح API للخادم (على هذا الـ bucket فقط)

1. **R2 ← Manage API tokens ← Create Account API token** (أو User API token إن لم يظهر).
2. الاسم مثلاً `<اسم الخادم>-backup`؛ **Permissions: Object Read & Write** (وليس Admin)؛ **Apply to specific buckets
   only** ← الـ bucket وحده؛ **TTL: Forever**؛ **Client IP filtering: فارغ** (تغيّر عنوان الخادم عند النقل يوقف النسخ بصمت).
3. انسخ **Access Key ID** و**Secret Access Key** فوراً إلى مدير كلمات المرور (السر لا يظهر مرة أخرى). أما **Token value**
   فلا نحتاجه: لا تحفظه ولا تلصقه في أي مكان.
4. لا تلصق المفاتيح في محادثة أو بريد أو تذكرة.

## 6. إنشاء إعداد rclone على الخادم (أمر واحد، لا يُظهر أي سر)

قبل هذه الخطوة يثبّت Claude نسخة من السكربت يملكها root في `/usr/local/share/<NAME>/`، ويرسل لك بصمتها (sha256) في
المحادثة. لا تشغّل السكربت من مجلد يستطيع Claude الكتابة فيه، لأنك تشغّله بصلاحية root.

في **جلسة SSH خاصة بك** (وليس الطرفية التي يقرؤها Claude)، وقارن البصمة بالتي أرسلها Claude قبل التشغيل:
```bash
unset HISTFILE
sha256sum /usr/local/share/<NAME>/owner-setup-s3.sh
sudo bash /usr/local/share/<NAME>/owner-setup-s3.sh --name <NAME>
```
يسألك بالترتيب: المزوّد (`r2`) ← اسم الـ bucket ← Account ID ثم Jurisdiction (Enter للافتراضي) ← **اسم مجلد هذا
الخادم** ← Access Key ID ثم Secret Access Key (**مخفيان**) ← عبارة التشفير مرتين ← عبارة الملح مرتين ← `YES` مخفية.
أي إدخال خاطئ يُطلب من جديد. ثم يختبر: الوصول إلى الـ bucket، وهل المفتاح أوسع من اللازم، وإن وُجدت نسخ سابقة هل
تفتحها العبارتان (ملف التحقق `keycheck` أو أسماء الملفات المشفّرة)، وكتابة ملف تجريبي مشفّر وقراءته وحذفه، وفي أول
إعداد يكتب ملف التحقق `keycheck` الذي يقرؤه كل تشغيل لاحق ليتأكد أن العبارتين هما نفسهما.

النتيجة المتوقعة: `All tests passed` ثم القيم **غير السرية**: احفظها في مدير كلمات المرور مع السكربت، وأرسل لي
**«rclone جاهز»**.

| الرسالة | المعنى والحل |
|---|---|
| `403` / `AccessDenied` | المفتاح خطأ أو غير مربوط بهذا الـ bucket |
| `NoSuchBucket` | اسم الـ bucket أو الـ Jurisdiction غير صحيح |
| `SignatureDoesNotMatch` | الـ Secret نُسخ ناقصاً |
| `WARN this key can list every bucket` | المفتاح أوسع من اللازم: أنشئ مفتاحاً على هذا الـ bucket فقط |
| `none opens with these passphrases` | العبارتان غير اللتين صُنعت بهما النسخ الموجودة |
| `another server` ثم `MOVE` | المجلد يستعمله خادم آخر: `MOVE` فقط عند نقل الخادم بعد إيقاف مؤقت القديم |
| `canary delete refused` | يوجد قفل على الـ bucket كله أو على المجلد كله: احذف ذلك القفل الخاطئ |

إذا فشل أي اختبار يحذف السكربت الإعداد الذي كتبه. أصلح القيمة في اللوحة ثم أعد التشغيل.

## 7. التنبيه: healthchecks.io (إلزامي قبل تشغيل المؤقت)

مثل خطوة SharePoint: فحص باسم `<NAME> <اسم الموقع>`، **Cron** `<دقيقة> <ساعة> * * *`، منطقة الخادم الزمنية، **Grace
90 minutes**، تنبيه إلى بريدك وبريد شخص ثانٍ. بعد التثبيت: `sudoedit /etc/default/<NAME>` وأزل `#` من سطر `HC_URL`
والصق الرابط.

## 8. ما يحدث بعد ذلك (Claude، بموافقتك في كل خطوة)

التثبيت ← `HC_URL` ثم `--preflight` ← الرفع الأول الكامل ← تشغيل تجريبي ليلاً ← أول تشغيل حقيقي ← التحقق، ومنه **محاولة
حذف ملف تجريبي في `daily/` يجب أن يرفضها R2** (دليل أن القفل يعمل) ← تفعيل المؤقت ← اختبار سلامة شهري وتجربة استرجاع
كاملة خلال الشهر الأول. ولتجربة الاسترجاع أنشئ مفتاحاً **Object Read** فقط بمدة قصيرة، واحذفه بعدها.

## 9. التكلفة (تقدير؛ تأكد من صفحة R2 Pricing)

يحسب Claude لهذا الخادم: حجم الملفات + نحو 20 نسخة قاعدة مضغوطة + الكود + الملفات المحذوفة. التخزين في R2 بسعر منخفض
لكل GB بعد حصة مجانية، والتنزيل (الاسترجاع) مجاني، والعمليات عادةً ضمن الحصة المجانية.

## 10. قرارات مطلوبة منك

1. موقع الـ bucket (وتسجيله في سجل البيانات الشخصية).
2. بريد إضافي عند الفشل (اختياري) إلى جانب healthchecks.
3. يوم النسخة الأسبوعية، وما يُضاف إلى الحزمة (بيانات تطبيقات أخرى، شهادات SSL).
4. طريقة حذف القديم: (أ) قواعد R2 تحذف والخادم يراقب فقط (موصى به: الخادم المخترق لا يستطيع تغيير القواعد)، أو (ب)
   الخادم يحذف بنفسه بلا قواعد حذف.

## 11. ملاحظات أمان

- ملف إعداد rclone على الخادم يحفظ المفتاح والعبارتين بصيغة «مُعتّمة» قابلة للعكس، لذلك صلاحيته 600 للـ root فقط.
- من يحصل على root على الخادم يستطيع قراءة المفتاح وحذف مرآة `filedir`، لكنه **لا يستطيع** حذف نسخ القاعدة والإعدادات
  والكود قبل انتهاء أقفالها، ولا تغيير قواعد الحذف والقفل (تحتاج دخول لوحة Cloudflare).
- لقطات مزوّد الخادم تبقى طبقة مستقلة.
- **عند نقل الخادم:** يعطّل Claude المؤقت على القديم أولاً، ثم تشغّل سكربت الإعداد على الجديد بالعبارتين نفسيهما.
